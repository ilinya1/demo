# 学生宿舍管理系统 — 前端文档

> 依据当前代码编写（2026-09-09）。

前端为 **Vue 3 单页应用**，使用 Vite 构建、Element Plus 组件库，Pinia 做状态管理，Vue Router 做路由，ECharts 做图表，Axios 发请求。前后端分离，通过 `/api` 访问后端；默认走真实后端，也可回退本地 mock。

## 三、请求封装 `api/request.js`

- **mock ↔ 后端切换**：`const useMock = import.meta.env.VITE_USE_MOCK !== 'false'`。设 `VITE_USE_MOCK=false` 走真实后端；否则走 `src/mock/`。
- **axios 实例**：`baseURL = '/api'`，`timeout = 15000`。
- **请求拦截**：自动附加 `Authorization: Bearer <token>`。
- **响应拦截**：统一解包 `Result{code,msg,data}`；`code!==0` 弹 `ElMessage` 并 reject；HTTP 401 触发登出并跳转登录页。
- **统一入口**：`request({url,method,data,params})`，mock 分支与 axios 分支均 resolve `<data>`。

> 生产构建要求 `VITE_USE_MOCK=false`（见 `frontend/.env.production`），否则会用本地 mock、连不上后端。

## 五、状态管理 `store/user.js`

- 状态：`token`、`user`（`name` / `role` / `studentId` / `username` 等）。
- 动作：`login`（存 token 与用户信息）、`logout`（清登录态）。守卫据此区分管理员/学生、未登录跳转登录页。

## 六、页面职责要点

**管理员端**
- Dashboard：统计卡片、各楼栋入住率、卫生趋势、运营工作台（待办/积压/告警/动态）。
- Stat*：三张台账统计页（ECharts）。
- StudentList：学生列表 + 班级卡 + 内嵌**学院管理**（新增/编辑/删除）、重置密码入口。
- RoomList：房间 + 床位分布；Checkin/CheckoutAudit/CheckinRecord：入住与退宿业务。
- HygieneList/HygieneAdd：卫生登记（扣分项自动计分、照片上传）。
- RepairList/RepairType：报修处理与类型字典。
- Settings：系统参数、退宿原因字典。

**学生端**
- MyRoom：我的宿舍/室友；MyHygiene：我的卫生；CheckoutApply：退宿申请+撤销；RepairAdd：提交报修；MyRepair：进度；Profile：个人资料+改密。

## 七、关键交互约定（对后端契约）

- **照片**：卫生 `photos`、报修 `images` 为 base64（`data:image/...`）数组，经 JSON 存库（后端 `LONGTEXT`）；列表/详情用 `el-image` 预览。低分（<60）或涉及违规电器必须上传照片才可保存。
- **床位号**：后端 `bedNo` 返回**纯数字**（已归一化），前端在展示处拼接「号床/床」。
- **学院**：下拉选项来自 `GET /colleges`（数组 `[{id,name}]`）；改名后班级/学生学院联动。
- **退宿原因**：下拉来自 `GET /daily/checkout-reasons`（后端字典）；报修物品类型来自 `GET /daily/repair-types`。
- **分页**：列表接口返回 `{list,total}`；前端按 total 显示分页。

## 八、运行与构建

```bash
cd frontend
npm install        # 首次
npm run dev        # 开发：http://localhost:3001，/api、/uploads 代理到 :8080
npm run build      # 生产构建 → dist/
npm run preview    # 本地预览构建产物
```

- 环境变量：`.env.development`（dev）；`.env.production`（build）。均含 `VITE_USE_MOCK=false`。
- 代理：`vite.config.js` 中 `/api` 与 `/uploads`（rewrite 为 `/api` + 路径）代理到 `http://localhost:8080`。

## 九、与后端联调注意

- 后端 `context-path=/api`，前端 `baseURL=/api` 对齐。
- 401 会登出并回登录页；业务失败由 `request.js` 统一弹出后端 `msg`。
- 生产部署用 nginx 托管 `dist/` 并把 `/api`、`/uploads` 反代到后端（见 `frontend/nginx/default.conf` 与《部署文档》）。
