# 学生宿舍管理系统 — 功能模块说明

> 本文档已按项目当前代码与实现同步更新（2026-09-09），描述均为**已实现**内容；未实现项在文末「二期规划」中单独标注。

## 一、系统概述

面向**管理员（宿管）**与**学生**两类用户，提供学生/班级/学院/楼栋/房间/床位等基础数据、入住退宿业务、卫生检查与报修、统计仪表盘、个人中心与系统设置等核心功能。

- **技术栈**：前端 Vue 3 + Element Plus + Pinia + Vue Router + ECharts，构建 Vite；后端 Spring Boot + MyBatis-Plus + JWT；数据库 MySQL 8。
- **架构形态**：前后端分离。后端统一 REST 接口（context-path `/api`）并做 JWT 鉴权；前端默认走真实后端，也可回退本地 mock。
- **使用方式**：管理员经 Web 后台日常管理；学生经网页查看个人住宿、卫生结果、退宿申请与提交报修。

## 二、角色与权限

| 角色 | 权限范围 | 主要功能 |
| ---- | ---- | ---- |
| 管理员（宿管） | 全部管理功能 | 学生/班级/学院、楼栋/房间/床位、入住退宿、卫生检查、报修处理、统计、系统设置、个人中心 |
| 学生 | 仅查看 + 提交 | 我的宿舍、我的卫生、退宿申请、提交报修、报修进度、个人中心 |

> 仅两类角色，通过 `sys_user.role`（ADMIN / STUDENT）区分，无复杂 RBAC。

## 四、模块详细功能

### 4.1 登录鉴权与账号
| 功能点 | 说明 |
| ---- | ---- |
| 登录 | 管理员/学生按账号密码登录，签发 JWT（有效期 720 分钟） |
| 身份识别 | 登录后按 role 展示管理员/学生不同菜单 |
| 修改密码 | 登录用户改密，需原密码且新密码 6-20 位（个人中心通用组件 `PasswordForm.vue`） |
| 重置学生密码 | 管理员将学生密码重置为默认 `123456`；无账号学生自动创建 STUDENT 账号 |
| 退出登录 | 清除本地登录态 |

### 4.2 仪表盘与统计
| 功能点 | 说明 |
| ---- | ---- |
| 仪表盘 | 统计卡片（在校学生/楼栋/房间/入住率）、各楼栋入住率柱状图、近 4 周卫生平均趋势、运营工作台（待办/积压/告警/最新动态） |
| 入住率统计 | 台账报表：卡片 + 分楼栋入住率 + 近 6 月入住退宿趋势 |
| 卫生统计 | 卡片（总数/优秀/合格/不合格/均分）+ 近 4 周均分 + 结果分布 |
| 报修统计 | 卡片（总数/完成）+ 类型分布 + 近 6 月趋势 |
| 数据实时性 | 全部统计由后端基于数据库实时聚合，非写死 |

### 4.3 基础数据
| 功能点 | 说明 |
| ---- | ---- |
| 学院管理 | 学院 CRUD；重名校验；改名级联同步班级/学生的学院；删除前引用拦截 |
| 班级管理 | 班级 CRUD；名称唯一；删除时班内有学生则拦截 |
| 学生管理 | 学生 CRUD；重置密码入口；删除在住学生时联动释放床位/重算房间/清理入住 |
| 楼栋管理 | 楼栋 CRUD（名称/楼层数/房间数/管理员） |
| 房间管理 | 房间 CRUD；容量与床位行数一致性由 Service 保证；已住房间禁止删除；床位分布查看 |
| 床位 | `dorm_bed` 独立建模，支持入住时床位分配与占用状态 |

### 4.4 住宿业务（入住 / 退宿）
| 功能点 | 说明 |
| ---- | ---- |
| 入住登记 | 选学生→楼栋→房间→空闲床位，事务内写 `check_in`(含快照) + 占用床位 + 更新学生/房间状态 |
| 退宿-学生申请 | 学生提交退宿申请（原因/计划日期/说明），可撤销 |
| 退宿-管理员审核 | 对待审核申请执行通过/驳回（驳回可填意见） |
| 退宿-直接办理 | 管理员直接退宿（`check_out.source=direct`，区别于申请 `apply`） |
| 入住记录 | 分页查询入住/退宿记录，退宿按时间区间统计 |
| 我的宿舍 | 学生查看当前宿舍/床位/室友 |

### 4.5 日常管理
| 功能点 | 说明 |
| ---- | ---- |
| 卫生检查 | 登记（楼栋/房间/日期/检查人/扣分项自动计分/照片/评语）；低分或违规电器必传照片；列表查询与详情照片预览 |
| 报修管理 | 学生提交报修（位置回显/物品类型/描述/照片/联系电话）；管理员查看详情并处理（处理人/说明/完成） |
| 报修类型字典 | 报修类型 CRUD；被引用不可删；供下拉与统计 |
| 退宿原因字典 | 原因 CRUD；被退宿申请引用不可删；供学生申请下拉 |

### 4.6 系统设置与个人中心
| 功能点 | 说明 |
| ---- | ---- |
| 系统参数 | 系统名称/欢迎语/联系电话/邮箱 可查改，支持恢复默认（落库 `sys_parameter`，登录页/侧边栏品牌联动） |
| 个人中心-管理员 | 查看/修改联系电话、邮箱；改密 |
| 个人中心-学生 | 查看/修改联系电话、紧急联系人；改密 |

## 五、学生端页面

| 页面 | 功能 |
| ---- | ---- |
| 我的入住信息 | 查看当前楼栋/房间/床位/室友 |
| 我的卫生检查 | 查看本宿舍卫生记录 |
| 退宿申请 | 提交申请 + 我的申请记录（撤销） |
| 提交报修 | 报修位置自动回显、物品类型下拉、上传照片 |
| 报修进度 | 查看自己报修单及处理人/电话/说明 |
| 个人中心 | 资料维护 + 改密 |

## 六、数据库（13 张表）

| 表 | 说明 | 表 | 说明 |
| ---- | ---- | ---- | ---- |
| student | 学生（学号主键，含住宿状态冗余） | `dorm_bed` | 床位 |
| class | 班级 | check_in | 入住/退宿记录（含快照、source） |

| sys_parameter | 系统参数 | | |

> 完整字段与逻辑外键见《数据库设计说明.md》。种子数据：班级 8、学生 24、学院 3、楼栋 3、房间 18、床位 72、入住/退宿记录 20、退宿申请 6、卫生 9、报修 12。

## 七、测试与运行

- **测试**：9 个测试类、30 个 `@Test`，覆盖鉴权/基础数据/学院/住宿/日常/统计/个人中心/系统设置/mapper 冒烟/上下文加载；使用独立测试库 `dorm_manager_test`（`@ActiveProfiles("test")`），不污染演示库。
- **演示账号**：管理员 `admin/123456`；学生 `2023010101/123456` 等（其余学生可由管理员重置密码自动建号）。
- **端口**：后端 8080（`/api`）；前端 dev 3001（`/api`、`/uploads` 代理到 8080）。
- **mock ↔ 后端**：`frontend/.env.development` 设 `VITE_USE_MOCK=false` 走真实后端；不设则走 `frontend/src/mock/` 本地 mock。
- **建库**：执行 `docs/sql/init.sql` 重建演示库。
