本设计基于以下文档统一梳理，确保**原型图字段 ↔ 数据库字段 ↔ 功能模块**三方一致：

- `prototype/` HTML 原型图（共 24 个页面：管理员端 17 + 学生端 6 + 入口 1，已修复 3 处字段问题）

## 三、表结构详情

### 3.1 sys_user — 用户表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, 自增 | 主键ID |
| username | VARCHAR(50) | NOT NULL, 唯一 | 登录账号 |
| password | VARCHAR(100) | NOT NULL | 密码（BCrypt加密） |
| role | VARCHAR(20) | NOT NULL | 角色：ADMIN-管理员 / STUDENT-学生 |
| student_id | BIGINT | 可空 | 关联学生ID（学生角色时必填） |
| status | TINYINT | NOT NULL, 默认 1 | 状态：1-启用 / 0-禁用 |
| create_time | DATETIME | 默认当前时间 | 创建时间 |
| update_time | DATETIME | 自动更新 | 更新时间 |

### 3.2 student — 学生信息表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, 自增 | 主键ID |
| student_no | VARCHAR(20) | NOT NULL, 唯一 | 学号 |
| name | VARCHAR(50) | NOT NULL | 姓名 |
| gender | VARCHAR(10) | NOT NULL | 性别：男/女 |
| college | VARCHAR(50) | NOT NULL | 学院 |
| major | VARCHAR(50) | NOT NULL | 专业 |
| class_name | VARCHAR(50) | NOT NULL | 班级 |
| phone | VARCHAR(20) | 可空 | 联系方式 |
| emergency_contact | VARCHAR(50) | 可空 | 紧急联系人 |
| emergency_phone | VARCHAR(20) | 可空 | 紧急联系电话 |
| status | VARCHAR(20) | 默认'在校' | 状态：在校/毕业/退学/休学 |
| create_time / update_time | DATETIME | — | 创建/更新时间 |

索引：student_no 唯一索引；name、college、class_name 普通索引。

### 3.3 dorm_building — 楼栋表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, 自增 | 主键ID |
| building_no | VARCHAR(20) | NOT NULL, 唯一 | 楼栋编号 |
| building_name | VARCHAR(50) | NOT NULL | 楼栋名称 |
| floor_count | INT | NOT NULL | 楼层数 |
| manager | VARCHAR(50) | 可空 | 楼栋管理员 |
| create_time / update_time | DATETIME | — | 创建/更新时间 |

> 楼栋列表页的"房间数、床位数、已住人数、入住率"均为统计字段，由 dorm_room 与 check_in 聚合查询得出，不冗余存储。

### 3.4 dorm_room — 房间表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, 自增 | 主键ID |
| building_id | BIGINT | NOT NULL, 逻辑外键→dorm_building | 所属楼栋ID |
| room_no | VARCHAR(20) | NOT NULL | 房间号 |
| floor | INT | NOT NULL | 楼层 |
| room_type | VARCHAR(20) | NOT NULL | 房间类型：四人间/六人间/八人间 |
| bed_count | INT | NOT NULL | 床位容量 |
| status | VARCHAR(20) | 默认'空闲' | 空闲/部分入住/已满/维修中 |
| create_time / update_time | DATETIME | — | 创建/更新时间 |

- 唯一约束：(building_id, room_no) — 同一楼栋内房间号唯一
- 索引：floor、status
- **status 计算规则**：已住人数 = 0 → 空闲；0 < 已住人数 < bed_count → 部分入住；已住人数 = bed_count → 已满；"维修中"由管理员手动标记并覆盖其他状态

### 3.5 check_in — 入住记录表（含退宿信息）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, 自增 | 主键ID |
| student_id | BIGINT | NOT NULL, 逻辑外键→student | 学生ID |
| room_id | BIGINT | NOT NULL, 逻辑外键→dorm_room | 房间ID |
| bed_no | VARCHAR(20) | NOT NULL | 床位号（如：1号床） |
| check_in_date | DATE | NOT NULL | 入住日期 |
| remark | VARCHAR(255) | 可空 | 入住备注 |
| status | VARCHAR(20) | 默认'在住' | 在住/已退宿 |
| check_out_date | DATE | 可空 | 退宿日期（退宿后填写） |
| check_out_reason | VARCHAR(50) | 可空 | 毕业离校/休学/退学/调宿/其他 |
| check_out_remark | VARCHAR(255) | 可空 | 退宿备注 |
| create_time / update_time | DATETIME | — | 创建/更新时间 |

- 索引：student_id、room_id、status、check_in_date
- **设计说明**：入住与退宿合并为一张表（1 条记录描述一次完整住宿生命周期），退宿即更新记录而非新增，避免 check_out 冗余表。同一学生在不同时期可有多条记录（含调宿）。

### 3.6 hygiene_check — 卫生检查记录表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, 自增 | 主键ID |
| check_date | DATE | NOT NULL | 检查日期 |
| building_id | BIGINT | NOT NULL, 逻辑外键→dorm_building | 楼栋ID |
| room_id | BIGINT | NOT NULL, 逻辑外键→dorm_room | 房间ID |
| score | INT | NOT NULL | 评分（0-100） |
| result | VARCHAR(20) | NOT NULL | 优秀/合格/不合格 |
| inspector | VARCHAR(50) | NOT NULL | 检查人 |
| deduction_items | VARCHAR(255) | 可空 | 扣分项（逗号分隔） |
| comment | VARCHAR(500) | 可空 | 评语 |
| status | VARCHAR(20) | 默认'草稿' | 草稿/已发布 |
| create_time / update_time | DATETIME | — | 创建/更新时间 |

- **result 判定规则**：score ≥ 90 → 优秀；70 ≤ score < 90 → 合格；score < 70 → 不合格（系统自动判定，允许手动调整）
- 学生端查看本宿舍记录：按 room_id 查询且 status='已发布'

### 3.7 repair_order — 报修单表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, 自增 | 主键ID |
| repair_no | VARCHAR(30) | NOT NULL, 唯一 | 报修单号（如 BX20260901001） |
| student_id | BIGINT | NOT NULL, 逻辑外键→student | 报修学生ID |
| room_id | BIGINT | NOT NULL, 逻辑外键→dorm_room | 房间ID |
| contact_phone | VARCHAR(20) | 可空 | 联系电话（报修人提交时留存，便于维修联系） |
| item | VARCHAR(50) | NOT NULL | 灯管/水龙头/空调/门锁/床铺/桌椅/其他 |
| description | VARCHAR(500) | NOT NULL | 问题描述 |
| images | VARCHAR(1000) | 可空 | 图片路径（JSON数组） |
| status | VARCHAR(20) | 默认'待处理' | 待处理/处理中/已完成 |
| handler | VARCHAR(50) | 可空 | 处理人 |
| handle_remark | VARCHAR(500) | 可空 | 处理说明 |
| handle_time | DATETIME | 可空 | 处理时间 |
| create_time / update_time | DATETIME | — | 创建/更新时间 |

- 报修单号生成规则：`BX + yyyyMMdd + 3位流水号`
- 报修位置（楼栋+房间）由 room_id 关联查询，不冗余存储

### 3.8 notice — 通知公告表（预留，二期）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|

| title | VARCHAR(100) | NOT NULL | 标题 |
| content | TEXT | 可空 | 内容 |
| publisher | VARCHAR(50) | 可空 | 发布人 |
| publish_time | DATETIME | 可空 | 发布时间 |
| create_time / update_time | DATETIME | — | 创建/更新时间 |

## 五、外键策略（逻辑外键）

本系统**不使用数据库物理外键（`FOREIGN KEY`）约束**，统一采用**逻辑外键**方案，引用完整性交由**后端 Service 层**保证：

- 各表关联字段（`student_id`、`room_id`、`building_id`）仅保留普通 `KEY` 索引用于关联查询性能，**不建立** `FOREIGN KEY` 物理约束。
- 引用完整性（如入住时校验学生、房间存在且床位充足；报修时校验学生、房间存在；检查记录校验楼栋、房间存在等）在**应用层**通过业务校验实现。
- 删除/修改主键等数据维护由业务规则控制（如房间、楼栋存在在住记录时禁止直接删除），避免物理外键级联带来的僵化。

**选择逻辑外键的原因**：
1. 兼容学生信息的 **Excel 批量导入**（导入顺序或中间态不受 FK 强校验限制）；
2. 入住登记高并发写入时避免外键锁，降低死锁风险（配合 `SELECT ... FOR UPDATE` 校验床位，见第六章）；
3. 与 MyBatis-Plus / Spring Boot 分层架构一致，约束收敛到应用层，便于软删除与审计留痕。

## 六、业务流转与数据联动

| 业务动作 | 数据联动 |
|---------|---------|
| 入住登记 | 新增 check_in 记录（status=在住）→ 重算 dorm_room.status |
| 退宿登记 | 更新 check_in（status=已退宿、check_out_* 字段）→ 重算 dorm_room.status |
| 调宿 | 原记录退宿（原因=调宿）→ 新增新房间 check_in 记录 |
| 卫生检查登记 | 新增 hygiene_check（status=草稿）→ 发布后 status=已发布 |
| 提交报修 | 新增 repair_order（status=待处理） |
| 报修处理 | 更新 repair_order.status（处理中→已完成）+ handler/handle_remark/handle_time |

**并发控制要点**：
- 入住时需校验房间剩余床位（bed_count − 在住人数 > 0），建议在事务中 `SELECT ... FOR UPDATE` 防止超卖
- 同一床位同一时间段只允许一条在住记录（业务层校验）
