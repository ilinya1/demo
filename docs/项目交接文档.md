## 一、项目定位

学生宿舍管理系统面向**管理员（宿管）与**学生两类角色，覆盖宿舍与房间管理、入住退宿管理、卫生检查、报修、学生信息、统计查询等核心业务，实现宿舍管理的信息化。

- 规划技术栈：前端 Vue 3 + Element Plus（前后端分离），后端 Spring Boot + MyBatis-Plus，数据库 MySQL 8

- 角色：仅区分管理员 / 学生，通过用户表的角色字段识别，无复杂 RBAC

- 已定核心闭环：登录 → 学生/宿舍 → 入住退宿 → 卫生检查/报修 → 统计

## 四、接下来要做什么

以下按优先级顺序推进，v3.0 完成后进入二期预留模块：

### P0 — 后端基础框架

- Spring Boot 工程扩展：引入 MyBatis-Plus 与 MySQL 驱动、JWT 工具、统一返回体（code / message / data）、全局异常处理。

- 依据 `init.sql` 生成 8 张表对应的实体 / Mapper / Service 骨架。

- 实现登录校验与角色区分（管理员 / 学生）。

### P1 — 基础业务

- 学生信息管理：增删改查、按学号 / 姓名 / 学院 / 班级查询、Excel 批量导入导出、状态管理（在校 / 毕业 / 退学 / 休学）。

- 楼栋与房间管理：楼栋维护；房间维护；房间状态自动计算（依据入住人数，含"维修中"标记）。

- 入住退宿：入住校验（床位充足、同一床位唯一）、退宿更新（含调宿处理）、入住历史查询。

### P2 — 日常业务

- 卫生检查：记录登记与发布、按楼栋 / 房间 / 日期 / 结果查询、结果由评分自动判定。

- 报修：学生提交（含图片 / 联系电话）、管理员处理状态流转（待处理 → 处理中 → 已完成）、报修进度查询。

### P3 — 统计报表

- 入住统计：各楼栋 / 房间入住率、空床位、退宿率。

- 卫生统计：平均分、合格率、优秀 / 不合格宿舍数。

- 报修统计：报修数量、完成率、类型分布、平均处理时长。

### 二期预留（暂不实现）

- 调宿 / 换宿独立流程、通知公告（`notice` 表）、晚归考勤、水电费管理、违纪管理。

## 五、接手注意事项

- **外键约定**：数据库不建物理外键，引用完整性依赖后端 Service 层校验，业务代码不得绕过该校验直写数据。

- **房间状态计算**：空闲 / 部分入住 / 已满由入住人数比对床位容量得出；"维修中"为手动标记且优先于其他状态。

- **并发与数据一致性**：入住时需在事务内校验剩余床位（建议 `SELECT ... FOR UPDATE`），同一床位同一时段仅允许一条在住记录。

- **登录与密码**：`init.sql` 中管理员 `password` 为占位哈希，部署前需通过后端初始化改为真实 BCrypt 哈希。

- **前端现状**：目前为静态原型，跳转与保存均为模拟（`showMsg` 弹提示、`openModal` 弹窗），v3.0 需替换为真实接口调用。

- **技术栈落地确认**：文档规划前后端分离（Vue 3 + Element Plus），当前仓库 `prototype/` 为纯 HTML 静态原型，后续前端工程搭建方式（vue-cli / Vite）需按团队基建确定。
